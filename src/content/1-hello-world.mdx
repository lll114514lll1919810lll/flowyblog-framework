## 文章从哪来

文章是 `src/content/` 下的 `.mdx` 文件，文件名（不含扩展名）就是 URL 里的 slug。比如 `10-hello-world.mdx` 对应 `/blog/10-hello-world`。新建文件、开头写一段 metadata，`pnpm dev` 下保存即可生效：

```tsx
export const metadata = {
  title: "文章标题",
  date: "2026-10-11", // YYYY-MM-DD，列表按它倒序排列
  publishedAt: "2026-10-11T09:00", // 可选，同日多篇时用它精确排序
  description: "一句话说明读者能获得什么。",
  cover: "/images/cover.png", // 可选，真实封面图（放 public/images/ 下）
  tags: ["示例"],
  draft: true, // 可选，true 时不出现在列表和搜索里
}
```

这段不是 YAML frontmatter，而是真正的 JavaScript 导出。如果某篇文章忘了写 metadata，它不会让构建失败，而是以「未命名文章」的身份出现在列表里，方便你发现漏了。

## 常用排版元素

正文就是普通 Markdown。标题从 `##` 开始（`#` 已被页面头部占用），一段只说一件事，段落中间不要手动换行——软换行在渲染后会变成空格，中文段落里会显得很怪。

> 引用块适合放强调性的一句话，或者补充说明。不要拿它当普通段落用。

无序列表适合并列项，有序列表适合有先后步骤的内容：

1. 新建 `.mdx` 文件
2. 写好 metadata
3. 保存，浏览器里确认渲染结果

行内代码用反引号包起来，比如 `pnpm dev`、`src/content/`。表格适合做参数或选项的对照：

| 元素 | 写法 | 适合的内容 |
| --- | --- | --- |
| 代码块 | 三个反引号包裹 | 命令、配置、代码 |
| 图片 | `![alt](路径)` | 截图、示意图 |
| 链接 | `[文字](URL)` | 参考资料来源 |

## 标题里的行内代码："draft" 开关

标题里也能写行内代码（比如 "draft"）。生成目录锚点时会先剥掉反引号等标记符号，再用剩下的纯文本算 slug，所以锚点仍然是干净的中文加英文组合，不会带一串符号。

## 代码块

代码块自带语言标签和复制按钮，支持常见语言的高亮：

```bash
pnpm dev        # 本地开发，http://localhost:3000
pnpm build      # 生产构建
pnpm typecheck  # 类型检查
```

代码块前面用一两句话说明它演示什么，后面说明关键结果或读者应该注意的地方，别让代码孤零零地杵在正文里。

## 图片怎么写

图片文件放进 `public/images/`（可以再建子目录分类），正文里用相对根路径的绝对地址引用：

```markdown
![示例图片的描述文字](/images/example.png)
```

`alt` 必须写，它是图片打不开时的兜底，也是读屏用户获取信息的唯一途径。截图类的图片建议控制宽度，正文列的宽度上限约 1792px，超宽截图会被压缩到难以阅读。

## 写完之后

发布前建议按这个顺序过一遍：

1. `pnpm dev` 里从头通读，检查渲染结果里有没有异常空格（尤其是中文段落中间）
2. `pnpm typecheck` 和 `pnpm lint` 确认没有引入低级错误
3. `pnpm build` 跑一次完整构建——有些问题只在静态导出时暴露

确认没问题，文件提交后就是一篇正式文章。列表页、标签页、归档、搜索索引和 sitemap 都会自动更新，不需要额外登记。
