export const metadata = {
  title: "用 metadata 描述一篇文章",
  date: "2026-09-12",
  description: "metadata 各字段的含义、slug 的命名规则，以及几个容易踩的坑。",
  tags: ["指南", "框架"],
}

每篇文章开头的 `export const metadata` 是文章的身份证：列表、归档、标签、搜索和 sitemap 读的都是它。

## 字段一览

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 标题，同时用于页面 title 和分享卡片 |
| `date` | 是 | `YYYY-MM-DD`，列表按它倒序 |
| `publishedAt` | 否 | 同日多篇时用它精确排序 |
| `description` | 否 | 摘要，用于文章页头部分享卡片 |
| `tags` | 否 | 标签数组，自动生成标签页 |
| `draft` | 否 | `true` 时不出现在任何公开页面 |

## slug 的命名规则

文件名（去掉 `.mdx`）就是 URL 的一部分：`6-mdx-metadata.mdx` 对应 `/blog/6-mdx-metadata`。文件名开头的序号只是习惯用法，框架不解析它，文章排序完全由 `date` 决定——所以改文件名序号不会改变列表顺序，别被它骗了。

slug 一经发布就不要改：它出现在 URL、搜索索引和别人的引用里，改了等于换了一篇文章。

## 两个常见的坑

1. **正文开头不要写一级标题**。文章页已经用 `metadata.title` 渲染了标题，正文再写一个 `#` 会出现两个大标题，目录也不会收录它。
2. **metadata 是 JavaScript 对象，不是 YAML**。字符串要带引号，数组用方括号，写错了不会构建失败，但会以「未命名文章」的身份出现——列表里看到它，回头检查 metadata 就好。

写完保存，列表页、标签页、归档、搜索索引和 sitemap 全部自动更新，没有需要手动登记的地方。
